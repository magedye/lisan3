# سجل القرارات والأسئلة المفتوحة

| المعرف | القرار | الحالة | الأثر |
| --- | --- | --- | --- |

| DR-002 | الاستقراء القرآني الداخلي هو المسار الأول | ACCEPTED | المصادر الخارجية لا تحكم الاستنتاج ابتداءً. |

| DR-004 | الفصل بين الجذر والصيغة والتركيب والسياق | ACCEPTED | قاعدة منهجية عليا. |
| DR-005 | الدحض والبدائل إلزاميان للفرضيات الجوهرية | ACCEPTED | لا يكفي جمع المؤيدات. |
| DR-006 | عدم الترادف التام فرضية بحث لا رخصة لاختراع الفروق | ACCEPTED | يبحث النظام عن الفرق ويعلن عدم الحسم إذا لم يثبت. |
| DR-007 | الذاكرة ليست دليلًا بذاتها | ACCEPTED | يجوز استخدامها كفرضية تشغيلية مع إعادة تتبع الأصل. |
| DR-008 | الثقة والاكتمال والتحقق المستقل محاور منفصلة | ACCEPTED | تعرض منفصلة ولا تدمج في حالة واحدة. |
| DR-009 | Skill/Agent/Tool فصل وظيفي | ACCEPTED | المهارة = كيف؛ الوكيل = ماذا/متى؛ الأداة = تنفيذ حقيقي قابل للتحقق. |
| DR-010 | البنية المستهدفة هجينة | PROVISIONAL | واجهة حوارية + تنسيق وكيل/مسار + محرك مستقل حتمي للأدلة والتحقق والحساب، مع قابلية استبدال Gem/Opal. |
| DR-011 | Gem وOpal أدوات تنفيذ لا مصدر سلطة | PROVISIONAL | الأدوار المحددة في هذه الحزمة قابلة للمصالحة مع حزمة إعادة الاستخدام. |
| DR-012 | الأوزان والعتبات الرقمية غير معتمدة بعد | ACCEPTED | كل الأرقام المقترحة في إجابات الوكلاء تعتبر أمثلة تجريبية حتى معايرتها. |
| DR-013 | المصطلحات الحاكمة جزء من المنهج | ACCEPTED | يجب إصدارها وتغييرها بمراقبة أثر. |
| DR-014 | اسم العملية: التحليل الدلالي الاستقرائي | ACCEPTED | المعنى المرجح نتيجة؛ البيان الدلالي حزمة العرض؛ الترجيح الدلالي فعل/حكم داخل العملية. |
| DR-015 | المفهوم الجذري كيان منظم والنواة الدلالية محتواه المركزي | ACCEPTED | يحسم تعارض استخدام المصطلحين كمترادفين كاملين. |
| DR-016 | التحليل الأعمى المستقل مشروط لا دائم | ACCEPTED | يستخدم في النتائج الحرجة/المتنازعة أو بطلب المستخدم؛ المشغلات النهائية تنتظر المعايرة. |
| DR-017 | البحث المتجهي والرسم الدلالي اكتشاف لا إثبات | PROVISIONAL | لا يستخدم التشابه وحده كدليل دلالي. |

## 2. الأسئلة المفتوحة
| المعرف | السؤال | جهة الحسم | الأثر | الملاحظة |
| --- | --- | --- | --- | --- |
| OQ-001 | ملف النص القرآني المعتمد والقراءة/الرواية في النسخة الأولى | OWNER/REUSE-KIT | BLOCKS_DATA_IMPLEMENTATION | يجب حسم المصدر والإصدار والهاش والترخيص قبل بناء مدونة الإنتاج. |
| OQ-002 | مصدر التحليل الصرفي/النحوي البنيوي | REUSE-KIT/TECH | BLOCKS_STRUCTURAL_LAYER | يجب تحديد ما إذا كان QAC أو تحليل محلي أو مزيجًا، وما الحقول المسموح بها. |
| OQ-003 | الدور الدقيق للبيان النبوي الصحيح داخل سياسة المصادر | OWNER/METHODOLOGY | BLOCKS_EXTERNAL_SOURCE_POLICY | الوثيقة المنهجية تمنحه رتبة خاصة؛ يحتاج قرارًا صريحًا للمشروع الجديد. |
| OQ-004 | نموذج معايرة الثقة وأوزانه وعتباته | EVALS | BLOCKS_CALIBRATED_PERCENTAGES | لا تعتمد النسب النهائية قبل benchmark ومعايرة. |
| OQ-005 | مشغلات التحقق الأعمى المستقل | EVALS | DOES_NOT_BLOCK_CORE | تحدد من نتائج التجارب: تقارب البدائل، أهمية النتيجة، شك التسرب، إلخ. |
| OQ-006 | التقنية النهائية للمحرك المستقل والتخزين | REUSE-KIT/ARCH | BLOCKS_PLATFORM_COMMITMENT | العقد المنطقي ثابت؛ اختيار Python/FastAPI/SQLite أو غيره بعد المصالحة. |
| OQ-007 | حدود استخدام Gem وOpal في المنتج النهائي | PLATFORM/ARCH | DOES_NOT_BLOCK_LOGICAL_CORE | قد يكونان واجهة/تنسيق أو مجرد بيئة prototyping. |
| OQ-008 | سياسة المصادر الخارجية التفصيلية: معاجم، تفاسير، شعر، نقوش، لغات سامية، دراسات | METHODOLOGY | BLOCKS_EXTERNAL_COMPARISON_MODULE | يجب تحديد أدوارها وترتيبها ودرجة استقلالها. |
| OQ-009 | دعم تعدد القراءات في النسخة الأولى | OWNER/PRODUCT | DOES_NOT_BLOCK_SINGLE_PROFILE_MVP | إذا لم يدعم MVP التعدد، يجب تثبيت ملف قراءة واحد وعدم دمج غيره. |
| OQ-010 | سياسة النشر والمشاركة والهوية متعددة المستخدمين | PRODUCT | DOES_NOT_BLOCK_RESEARCH_CORE | لم يحسم في النقاش؛ لا يفترض Multi-user أو Public publishing. |

## 3. قاعدة التعامل
السؤال المفتوح ذو أثر `BLOCKS_*` يمنع تنفيذ الجزء الذي يعتمد عليه. لا يجوز تحويل «اقتراح وكيل» إلى قرار لمجرد سد الفراغ.
