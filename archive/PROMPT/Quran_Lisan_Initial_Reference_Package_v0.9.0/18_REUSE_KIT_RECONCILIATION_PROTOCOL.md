# بروتوكول مصالحة NEW_LISAN_PROJECT_REUSE_KIT

## 1. الهدف
عند رفع حزمة إعادة الاستخدام من Lisan3، لا تنسخ مكوناتها تلقائيًا ولا تعاملها كسلطة أعلى. تستخدم لاكتشاف ما ينقص الحزمة الحالية، والأشياء المجربة التي يمكن إعادة استخدامها، والدروس التي تستدعي تعديل قرارنا.

## 2. خطوات المصالحة
1. تثبيت snapshot للحزمة الحالية v0.9.0.
2. جرد كل عنصر في `NEW_LISAN_PROJECT_REUSE_KIT` ومصدره داخل Lisan3.
3. تصنيفه: `REUSE_AS_IS / ADAPT / REFERENCE_ONLY / DO_NOT_REUSE / OPEN_QUESTION`.
4. ربطه بوثيقة أو متطلب أو قرار في هذه الحزمة.
5. تحديد نوع التغيير: إضافة، تعديل، إلغاء، أو لا أثر.
6. حل التعارضات بحسب مبادئ المشروع الجديد، لا بحسب أسبقية Lisan3.
7. إجراء مراجعة خاصة لأي عنصر يزيد حوكمة AI ويقلل سلطة الترجيح.
8. مراجعة خاصة لعقود المصادر، البيانات البنيوية، الدحض، الاسترجاع، والاختبارات؛ فهي أكثر مناطق reuse المتوقعة قيمة.
9. تحديث السجلات والوثائق في commit/revision واحد واضح.
10. إصدار `Final Release Package v1.0` مع Change Log ومصفوفة أثر.

## 3. معايير تبني عنصر من Lisan3
نتبناه إذا:
- يحسن سلامة المصدر/الدليل أو قابلية التتبع أو الاختبار أو الصيانة.
- لا يحول AI مجددًا إلى «مقترح فقط» خلاف قرار المشروع الجديد.
- لا يدخل lifecycle أو publication governance لا حاجة لها.
- يحل حاجة مثبتة دون تضخم مكدس الأدوات.
- يمكن تفسير أثره على النتائج والاختبارات.

## 4. مخرجات المصالحة النهائية
- `RECONCILIATION_REPORT.md`
- `CHANGELOG_v0.9_to_v1.0.md`
- `FINAL_DECISION_REGISTER.csv`
- `FINAL_CONTROL_REGISTRY.csv`
- `FINAL_TERMINOLOGY_REGISTRY.csv`
- `Final Release Package` الموحد.

## 5. شرط الإصدار النهائي
لا يسمى الإصدار `Final Release Package` قبل:
- معالجة جميع P0 open questions أو تحويلها إلى deferred صريح لا يؤثر في البناء.
- حسم ما نقل من Lisan3 وما رفض ولماذا.
- تثبيت ملف النص/البيانات البنيوية.
- تثبيت عقود المخرجات والأدلة.
- تحديد خطة معايرة الثقة حتى إن لم تنتهِ المعايرة بعد.
