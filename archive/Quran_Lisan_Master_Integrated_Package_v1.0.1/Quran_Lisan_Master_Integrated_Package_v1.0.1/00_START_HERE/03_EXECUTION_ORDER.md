# ترتيب التنفيذ الموصى به

هذا **ترتيب تنفيذي موصى به** وليس تحويلًا صامتًا لكل P1..P8 إلى قواعد كانونية.

## المرحلة 0A — Admission & Foundation (ابدأ هنا)
نفذ `04_FIRST_CODEX_REQUEST.md`.
الهدف: إدخال الحزمة إلى LISAN3 بصورة محافظة، التحقق من الحالة الحالية، تطبيق التوجيهات المالكية المقبولة فقط، وبناء أساس المعرفة الوصفية القابلة للتحقق.

## المرحلة 0B — Owner Decisions
بعد 0A، راجع `03_PRE_ANALYSIS/03_OPEN_OWNER_DECISIONS.md`. تعتمد فقط القرارات التي ما تزال ذات حاجة فعلية بعد فحص التنفيذ.

## المرحلة 0C — Calibration Readiness
تثبت المصادر البنيوية، الملف الوصفي للجذر، عزل الاكتشاف الداخلي عن الاختبارات الخارجية، ونماذج التحقق اللازمة. لا توجد حاجة إلى Gate جديد ما لم يظهر خطر لا تمنعه آلية أخف.

## المرحلة 1 — Calibration Batch
تشغيل دفعة صغيرة متنوعة فقط بعد نجاح 0A/0C. المنهج يجمد داخل الدفعة، وتلتقط كل العوائق والدروس دون تعديل صامت.

## المرحلة 2 — Expansion
لا تبدأ إلا إذا نجحت المعايرة ولم يظهر عيب عام يجعل التوسع يكرر خطأ منهجيًا.

## ما لا يبدأ الآن
- تحليل واسع لعشرات/مئات الجذور.
- تغيير UI أو معماريات غير مرتبطة.
- فرض معاني الحروف أو الصيغ كحقائق.
- اعتماد معنى معجمي/تراثي لمجرد وروده في مصدر.
