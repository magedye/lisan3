# بروتوكول التنفيذ والأرشفة

## قبل التنفيذ
- ملف الطلب الحالي يبقى داخل `00_START_HERE/04_FIRST_CODEX_REQUEST.md`.
- يسجل المنفذ Base SHA وحالة الشجرة قبل أي تغيير.

## عند إتمام الطلب
ينشئ المنفذ في مستودع LISAN3 سجلًا تاريخيًا غير حاكم، مثل:
`docs/history/lisan-execution/<phase-id>/`
ويحفظ فيه على الأقل:
- `REQUEST.md` نسخة حرفية من الطلب المنفذ.
- `RESULT.md` التقرير النهائي.
- `BASE_IDENTITY.txt` و`CANDIDATE_IDENTITY.txt`.
- `TEST_EVIDENCE.txt` أو روابط الأدلة.
- `CHANGED_PATHS.txt`.

ثم تصبح هذه المواد **أرشيف تنفيذ** وليست سلطة متقدمة على المنهج.

## ما لا يؤرشف بوصفه منتهي الصلاحية
مجموعة `INSEPARABLE_CORE` تبقى حية مع كل تشغيل حتى يصدر إصدار Master لاحق ينسخها صراحة.

## عدم الكتابة فوق التاريخ
أي تعديل لاحق يخلق Request/Result جديدين. لا تُعدّل نتائج تشغيل سابق لإظهارها وكأنها كانت مختلفة.
