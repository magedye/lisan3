# Explicit Anti-Reuse List

These items should not enter the first new-project operating method. A later trigger can reopen some decisions.

| Item | Why not reuse now | Condition that could make it useful later | Evidence basis |
|---|---|---|---|
| Lisan3 publication authority and release acceptance | New project is research/design-oriented; publication state does not measure semantic validity | A real public corpus/product with named release authority | Four-axis models, review/publication endpoints, legacy release schemas |
| Full four-axis status system | Epistemic/review/freshness/publication separation is conceptually sound but operationally heavy | Multiple users, publication and dependency invalidation at scale | Platform/model enums and status tests |
| Steward authority and commands | Exists for governed operational delegation, not root research | A real operational/steward user role | Steward service and Slice F tests |
| AI proposal-only restriction | Conflicts with owner’s explicit direction that AI may prefer semantic conclusions | Keep only if owner later retracts AI decision authority | Platform/backend AI policy and AI proposal test |
| Purity + Internal Lock as one mandatory gate | Current evaluator is largely unimplemented and monolithic blockage obscures partial valid findings | A validated new-project decision policy proves all checks mandatory for a specific product action | Gate/Purity services and five-root blocker |
| Exact Lisan3 gate/status labels | They are Lisan3 authority values, not universal methodology | Never import names without a new-project decision | Authority map and models |
| GovernanceRule/ChangeProposal/owner approval workflow | Premature bureaucracy for experimental method revisions | Stable production methodology with many dependent results/users | Slice E models/tests |
| ROOT_CARD/TERM_CARD/public-entry machinery | Presentation/read-model concerns do not establish semantics | A real publishing/UX requirement | Corrective addendum and legacy schemas |
| Current QAC adapter/alignment implementation | Fixture pipe format, semantic stripping by substring, discarded structure, tolerant alignment; canonical docs say real importer absent | Verified license/artifact plus real parser, persistence, reconciliation and tests | QAC docs/services/tests |
| Current static reproduction-manifest endpoint | Static tool list/simulated model and no exact AI replay can mislead | Replace with actual receipt aggregation and truthful replay level | `backend.main.get_run_reproduction_manifest` |
| Duplicate Root Core/Definition/Meaning/Concept fields without a terminology decision | Risks stylistic duplication and inconsistent confidence | Each field has a distinct tested consumer and definition | Skill presentation and models |
| Graph/vector layers in the first prototype | No demonstrated core need; can distract from semantic method and structural corpus | Exact retrieval baseline shows measured recall/traversal gap | Hybrid contract and R2 benchmark |
| Neo4j, Qdrant Server, Redis, Celery, Kafka, microservices, Kubernetes | No local prototype requirement | Measured scale/concurrency/deployment need | Tooling reference explicit non-adoptions |
| LangGraph alongside Opal | Duplicate workflow/state machinery | Opal/simple orchestrator demonstrably cannot express required branching/resume | Tooling §5.5 |
| External RAG inside internal induction | Risks source-role contamination and hidden traditional framing | A separate post-analysis external-comparison index with receipts | Hybrid §31 and Purity contract |
| Legacy owner/release/lock fields | Historical governance, not semantic evidence | Only for a future governed publishing product | Legacy reuse schemas |
| Fixed number of neighbors or universal top-K | Retrieval efficiency is not methodology | Never as a semantic rule; configurable search only | Skill neighbor rules and Hybrid Top-K |
| Uncalibrated numeric confidence | Model self-confidence/percentages lack empirical meaning | Calibration dataset demonstrates reliability | Skill §5 and current QualityProfile gaps |
| “Multiple Agents = independent evidence” | Correlated model/context produces repeated opinion, not independent evidence | Declare and satisfy a concrete independence class | Handoff agent policy plus agent inference |
| Whole-source trust | Mixed sources can contain permitted structure and prohibited semantics | Never; keep field-level roles | QAC admission/quarantine lesson |

## Anti-copy decision

No Lisan3 artifact was copied verbatim into `materials/`. The templates are concise adapted derivatives because exact copies would carry Lisan authority vocabulary, legacy status fields, or unnecessary ceremony. [TR-117]
