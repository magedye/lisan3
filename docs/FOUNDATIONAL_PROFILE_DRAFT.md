# FOUNDATIONAL_PROFILE_DRAFT

**status**: `DRAFT / NON_GATING`
**scope**: LISAN3 pre-analysis foundation (Owner Requests 01)
**authority**: derived only from **already-accepted** owner directives (Master
Package v1.0.1 `02_CURRENT_OWNER_DIRECTIVES/` + the preserved V2.1 base). This
draft **does not** create rules, gates, or a taxonomy. It is a consolidation for
review; each row cites an accepted source. Genuinely open items are listed in the
appendix and MUST NOT be adopted from this file.

Each premise carries the six governed fields:
**statement · authority · scope · methodological_effect · misapplication_risk ·
review_trigger.**

---

## FP-1 — Root semantic unity (NON_NEGOTIABLE)
- **Statement**: If a set of words/occurrences truly belongs to one root, that
  root has a constant unifying contribution demonstrable in every firmly-attributed
  occurrence after subtracting inflection/form/construction/context.
- **Authority**: `INT-OWN-ROOT-001/002`; `06_ROOT_SEMANTIC_UNITY_NON_NEGOTIABLE.md` §1/§11; `SUP-009`.
- **Scope**: root/derivation semantic analysis.
- **Methodological_effect**: failure to find the unifier → `UNRESOLVED / RESEARCH_INCOMPLETE`, not multiple arbitrary root meanings.
- **Misapplication_risk**: forced unification or fragmenting one root into ad-hoc meanings.
- **Review_trigger**: any accepted `ROOT_CONCEPT`; any `MULTIPLE_LEXICAL_UNITS` usage.

## FP-2 — Universal presence, no majority substitute
- **Statement**: One firmly-attributed occurrence the candidate cannot explain blocks it; 99/100 is not universality.
- **Authority**: `INT-OWN-ROOT-002` §3; `02_ROOT_MEANING_UNIVERSAL_PRESENCE.md`.
- **Scope**: acceptance/canonicalization of root-wide concepts.
- **Methodological_effect**: coverage is exact-set, never thresholded; an unresolved attribution blocks a completeness claim.
- **Misapplication_risk**: silently accepting a "dominant" meaning as universal.
- **Review_trigger**: any `UNIVERSAL`-scope claim reaching canonicalization.

## FP-3 — Descriptive knowledge before semantic reasoning
- **Statement**: What can be enumerated/counted/matched is derived once, verifiably, persisted, and reused — not re-guessed by an LLM per run.
- **Authority**: `INT-PRE-OWN-001`; `03_DESCRIPTIVE_KNOWLEDGE_BEFORE_SEMANTIC_REASONING.md`.
- **Scope**: all descriptive/structural data preceding semantic induction.
- **Methodological_effect**: research begins from a known, bounded, verified Root Descriptive Profile.
- **Misapplication_risk**: the model invents counts/occurrences; coverage cannot be proven.
- **Review_trigger**: before any root/lexeme semantic run; before a campaign batch.

## FP-4 — Data vs meaning; four knowledge levels
- **Statement**: A reviewable structural annotation is never presented as a direct textual fact; keep DIRECT_TEXTUAL_FACT vs QUALIFIED vs DISPUTED vs UNRESOLVED structural annotations distinct.
- **Authority**: required consequence of `INT-PRE-OWN-001` §2–§7; Request 01 §6.
- **Scope**: every structural-source ingestion and profile build.
- **Methodological_effect**: attribution-dependent counts are labelled qualified; disagreements preserved, never hidden.
- **Misapplication_risk**: a morphological analysis treated as textual truth.
- **Review_trigger**: any structural-source ingestion or profile build.

## FP-5 — External sources are hypothesis/test generators, not authority
- **Statement**: External scholarship (incl. Jabal's central meaning) generates hypotheses/tests/learning; never authority, no confidence bonus, never canonical.
- **Authority**: `INT-EXT-001..007`; `04_EXTERNAL_HYPOTHESIS_TESTING_CURRENT_POLICY.md`.
- **Scope**: any external claim entering the system.
- **Methodological_effect**: `Scholar said X → Hypothesis/Test`, never `→ Methodology changed`.
- **Misapplication_risk**: heritage/dictionary-first contamination; authority-by-reputation.
- **Review_trigger**: registering any external hypothesis.

## FP-6 — Rule claim ≠ author application
- **Statement**: A rule's soundness is judged separately from the quality of its author's individual applications.
- **Authority**: `04_EXTERNAL_HYPOTHESIS_TESTING_CURRENT_POLICY.md` §4–§5.
- **Scope**: evaluating external `METHOD_RULE` / application claims.
- **Methodological_effect**: `RULE_CLAIM` and `AUTHOR_APPLICATION` are recorded and tested independently.
- **Misapplication_risk**: accepting/rejecting a rule on example quality alone.
- **Review_trigger**: any external claim with both a rule and applied examples.

## FP-7 — Blind internal isolation; external must not masquerade
- **Statement**: Internal induction is isolated from external semantic sources; an external hypothesis tested early must be marked so it cannot pass as blind internal discovery.
- **Authority**: `INT-EXT` §9; `SUP-005 (REFINED)`; `06_SOURCE_ISOLATION_AND_EXTERNAL_COMPARISON.md`.
- **Scope**: hypothesis creation and internal/external comparison.
- **Methodological_effect**: hypothesis origin is explicit (`INDEPENDENT_INTERNAL_DERIVATION` vs `EXTERNAL_CANDIDATE`).
- **Misapplication_risk**: laundering a dictionary meaning as an internal discovery.
- **Review_trigger**: creating any hypothesis from an external source.

## FP-8 — Governed capture; owner ≠ assistant
- **Statement**: Every material request/idea/proposal is captured, classified, and dispositioned with rationale; an assistant proposal never becomes ACCEPTED without an owner approval reference.
- **Authority**: `INT-BOOT-001`; `01_GOVERNED_CAPTURE_CURRENT_POLICY.md`.
- **Scope**: all governance changes, findings, and decisions.
- **Methodological_effect**: no silent drop; no silent promotion.
- **Misapplication_risk**: assistant proposals hardening into rules.
- **Review_trigger**: any change proposal or methodology finding.

## FP-9 — Terminology clarity in new human-facing text
- **Statement**: New human-facing governing text prefers precise phrasing over ambiguous «دلالة» / «وحدة معجمية»; existing technical IDs are not renamed.
- **Authority**: `INT-OWN-TERM-001`; `05_TERMINOLOGY_CLARITY_DELTA.md`; `SUP-006`.
- **Scope**: prose/UX, not code tokens.
- **Methodological_effect**: clarity delta applies to documents, not schema/IDs.
- **Misapplication_risk**: a wide technical refactor that breaks compatibility.
- **Review_trigger**: authoring new governing/human-facing documents.

## FP-10 — Distinctiveness + falsifiability (universality is necessary, not sufficient)
- **Statement**: An accepted root meaning must also be non-empty, distinct from nearest roots, minimally loaded, and falsifiable.
- **Authority**: `06_ROOT_SEMANTIC_UNITY_NON_NEGOTIABLE.md` §9.
- **Scope**: preferring/canonicalizing a root concept.
- **Methodological_effect**: coverage + distinctiveness + a rejection condition are all required.
- **Misapplication_risk**: an empty/over-general "unifier" that explains everything.
- **Review_trigger**: preferring/canonicalizing any root concept.
